# clone 后还需要什么

仓库能提供程序、模板、配置示例和一套展示结果。完整运行所需资料与服务如下；不能把“程序完成”当作业务资料已经齐全。

| 项目 | 状态/需要提供 | 放置或配置 |
| --- | --- | --- |
| 同版本规划地物与规则包 | 本机已集中；clone需单独领取 | `roaddata/preprocessed/` |
| DEM与补充道路/生态GDB | 本机已集中；clone需单独领取 | `roaddata/dem/`、`roaddata/source/` |
| 参考原稿 | 本机已集中；clone需单独领取有权使用的文件 | `roaddata/reference/` |
| 规划后端 | 独立部署，需与本地数据的工程、坐标及版本匹配 | 本地配置 `planner_url`；鉴权 token 用环境变量 |
| 起终点与两条正式候选方案 | 测试路线不代表甲方确认；可自动搜索不同控制点路线，失败需调整数据/选点 | `start`、`end`、方案归档/自动生成配置 |
| LLM/VLM接入 | clone不带真实地址、模型账户或密钥 | 本地配置 `api_base`、`model_id`；`.env` 或环境变量 |
| 卫星底图 | 外部服务授权、网络、浏览器与地图接口可用；矢量底图可验证流程 | 规划系统底图配置；报告 `use_satellite`/`basemap_mode` |
| PDF渲染与字体 | 安装LibreOffice、中文字体和目标西文字体 | `soffice` 或系统PATH；本机`.tools`不上传 |
| 正式行政区边界 | 目前缺独立完整边界，现有地物的地名字段并不等价于完整区划面 | `admin_boundary`、`admin_name_field` |
| 照片、现场跨越和道路等级 | 图层不足以证明现场状态，缺失的不能凭模型编造 | `roaddata/materials/`，按素材示例填写 |
| 3.4.9—3.4.10相关专业调查/协议 | 需甲方提供真实确认件与专项口径 | supplemental示例，关联 `route_geometry_hash` 与 `source_file` |
| 停电方案/时间/窗口及专业意见 | 地物只能识别相关线路，不能推算出正式停电安排 | 已确认的专项材料 |
| 正式推荐方案与审批意见 | 缺少确认时不输出已批准结论 | 专家/甲方补充资料 |

仅负责 3.3.1、3.3.2 的开发者无需先补齐合规插件所有专业意见，但其描述所涉及的路线、地名、关键跨越及照片仍应有来源。空资料保留待核，禁止把缺失解释为无敏感点、无跨越或无需停电。

本轮是数据集中与迁移验证：完整三插件采用已有真实路线响应重新生成，模型关闭、使用矢量图；因此证明本地新路径可读、事实和文档链路可执行，不替代真实模型和卫星服务的在线验收。

## 必须向路径规划维护方一并领取的交接项

1. 可运行的 opt_v56 源码或匹配部署包（本报告仓库不包含），以及相应 environment.yml/部署环境和版本说明。
2. 完整预处理输出、所对应工程及坐标元数据，明确 PREPROCESS_MANIFEST 和报告 dataset 的版本一致关系。
3. 后端启动方式、监听地址/端口、如有鉴权则提供配置方法；底图使用时提供合法授权与联网条件。
4. 与该版本一致的接口文档集，至少覆盖 health/map/plan/progress/cancel 和控制点校验。
5. 如果希望首次不重新规划，还需交接完整地图快照、两条方案 request/response 和匹配配置；发布的展示PDF/Word不包含这些运行输入。

从源码安装、终端A启动后端、终端B安装报告端与联调的具体步骤已放入根 README。两个服务、两套环境、各自凭据和数据不可混淆。
